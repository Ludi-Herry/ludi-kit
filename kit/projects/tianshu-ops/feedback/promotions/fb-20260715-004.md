# Promotion Draft: Page-level authorization failures need a clear 403 state

- Feedback item: `fb-20260715-004`
- Status: `promoted`
- Target: `component`
- Action: `update-component`
- Destination: `components.manifest.json`
- Reviewer: `kit-maintainer`
- Reviewed at: `2026-07-15`

## Finding

Tianshu defines a full-page 403 response for missing route permissions, while current generated pages only disable isolated actions and cannot explain why protected content was not loaded or how the user can recover.

## Proposed Change

Promote a lightweight ForbiddenState with a fixed visual 403 cue, accessible title and description, and a constrained recovery action slot; add a real RBAC forbidden page that never renders protected data.

## Evidence

- The Tianshu platform brief explicitly requires both disabled permission actions and a 403 placeholder page.
- The RBAC route contains role, user, and permission data that must stay hidden when platform:rbac:read is absent.
- Empty data, API errors, and route authorization have different user meaning and need separate page semantics.
