# Data Table Rules

## 选型

- 需要分页、排序、选择、批量操作：`DataGrid`
- 少量只读小表：`Table`
- 少量键值属性：`DescriptionGrid`

## 结构

列表页数据区必须是 `DataSection > DataGrid`。工具栏放在 `DataSection.toolbar`，不要塞进表格内部。

## 固定列与窄屏

- 固定列必须声明宽度，并先从当前视口的可用宽度中扣除。
- 与固定列相邻的可见列必须保留其声明的最小可读宽度。空间不足时，按响应式优先级隐藏完整的低优先列，禁止留下被固定列遮住的表头或半截单元格。
- 最窄支持视口要检查横滚起点、中段和终点。`clientWidth === scrollWidth` 只证明页面没有外层横向溢出，仍需看图确认固定列、遮罩和相邻内容没有重叠。

## 状态

- loading 用组件的 `loading`。
- 空状态用 `empty`。
- 状态字段用 `Badge`，variant 由业务语义决定。

## 筛选、时间与标签

- 筛选频率、响应时间和条件复杂度决定常驻、收纳及提交方式，具体规则见 [interaction-decisions.md](./interaction-decisions.md)。条数阈值只是初选参考；已测延迟、接口负担和真实任务优先，不用示例比例冒充使用统计。
- 时间条件同时交代快捷区间与实际起止日期；最大跨度由业务合同确定，比较区间按 [data-visualization.md](./data-visualization.md) 处理。
- 多选标签溢出时控制输入框占高，保留已选数量与完整名单入口；触屏与键盘可读取完整名单，不能只靠 hover。
- “全选”要说明是当前结果、当前分组还是所有对象；新对象是否自动入选由业务规则决定。数量、筛选结果和最终操作集合保持一致。

来源：`<local-path-omitted>` 的筛选、时间、标签段。案例中的 3 项、90 天和 19/20 不是所有项目的固定参数。
