# Interaction Decisions Rules

六条跨页面的判断规则：确认分级、筛选区、空值与数值格式、脱敏分级、行操作、持续内容与通知。每条写清适用条件与边界，末行给出处。

组件名按底座换算：气泡确认对应 antd `Popconfirm`、Element Plus `ElPopconfirm`；对话框确认对应 kit `ConfirmDialog`、antd `Modal.confirm`、Element Plus `ElMessageBox`；轻提示对应 antd `message`、Element Plus `ElMessage`。所需组件不在当前 design pack 登记时，先按 [component-priority.md](./component-priority.md) 处理，不自造。

## 1. 确认分级：先问能不能撤销

适用条件：任何改变数据的动作（删除、停用、标记完成、批量变更、提交），在决定要不要加确认之前。

做法：先回答四问，再定档位。

1. 影响多大：是否涉及金额、权限、安全、对外可见或重要数据。
2. 能否撤销：几秒内可恢复，还是要人工处理，还是永久生效。
3. 用户怎样感知：技术上可逆、但用户会觉得回不来的，上调一档。
4. 是否紧急：安全告警、故障处置等，不增加确认步骤。

| 档位 | 条件 | 做法 |
| --- | --- | --- |
| A 直接执行 | 低影响且可撤销 | 点击即执行，用轻提示告知结果并带「撤销」；用户做下一个操作或 1 分钟内无操作，提示消失、撤销失效 |
| B 气泡确认 | 不可撤销，影响限于当前对象 | 在触发处用气泡确认，不离开当前页；写清对象与后果 |
| C 对话框确认 | 高影响且不可撤销（批量、金额、权限、数据丢失、对外可见） | 对话框加摘要：对象、数量、范围、后果；确认按钮用具体动词；需要时分步核对或强确认 |

高影响但可撤销的动作：直接执行，先展示预览或校验结果，并保留回退入口。

反例：

- 每次删除都弹对话框。用户会养成无脑点确认的习惯，既打断当前上下文，也拦不住误操作。
- 不可撤销的操作只给成功提示，没有确认。
- 确认文案只写「确定要删除吗？」，不写对象、数量和后果。
- 紧急场景要求多轮确认；或界面写「正在核验」，后台并没有对应检查。摩擦必须带来信息、控制权或保护，不能只是变慢。

与既有条款的关系：本条只决定要不要确认、用哪一档。确认框的写法与焦点行为仍按 [dialog-vs-drawer.md](../recipes/dialog-vs-drawer.md) 的 ConfirmDialog 一节。系统配置里的删除、重置、关闭核心服务属于 C 档，仍按 [settings.md](./settings.md) 用 `ConfirmDialog`。`components.manifest.json` 中 ConfirmDialog 的 `useWhen` 已按本条限定为 C 档（2026-09-30）。`kit-consumer` 目前没有气泡确认和轻提示组件，A、B 档先记录为 feedback，业务页不自造。

出处：知识库《B端交互十原则-交互前中后的完整回路》§足不出户；《战略性摩擦-按风险与可逆性校准交互速度》§四项判断、§摩擦要交付真实价值

## 2. 筛选区：常驻少量，其余收纳

适用条件：列表页筛选区（`FilterPanel` 或等价结构）。

做法：

- 常驻通常 3–4 项，只放真实任务中的高频条件，从左到右按高频到低频排；没有使用统计时不编造比例。输入类字段（ID、手机号）用搜索，选择类字段（状态、归属人）用筛选，搜索排在筛选前。
- 超过 4 项：高频平铺，低频折叠或进高级筛选。折叠适合 4–8 项；条件超过 2 排且含低频项时必须收纳；外露的标签超过 7 个时收纳。
- 「重置」：筛选项超过 3 个才提供，3 个及以下不放。结果为空时仍保留清除入口（见 [empty-loading-error.md](../recipes/empty-loading-error.md)）。
- 实时筛选还是「查询」按钮：按实测响应时间、请求成本和条件配置方式判断；少于 1000 条 / 多于 10000 条、400ms 只能作初选参考，不能替代实测。高成本请求、明显等待或条件配置到一半就请求没有意义时，用提交式查询；重置是否出现仍按本节筛选项规则。
- 按钮与筛选项同一行、靠右；同一行放不下才另起一行，仍靠右对齐。
- 默认记住上次筛选条件（可设保存周期，如 24 小时）；手机号、身份证号等隐私字段不记忆。高频组合允许保存为视图。
- 多条件默认「且」。出现「或」「非」时，用括号、缩进或虚线框把分组画出来。视图、阶段、状态等多层筛选并存时不藏优先级：阶段计数和可选项按当前已生效的条件重算，互斥的选项置灰并显示 0。

反例：

- 8 个筛选项全部常驻，占满两排。
- 只有 2 个筛选项却放了「重置」。
- 表格数据 5 万条仍每改一个条件就实时请求。
- 列表已被「运行异常」视图过滤，阶段条仍显示全量计数，点选后得到空结果。
- 手机号被记忆到下次会话。

组件现状：kit 的 `FilterPanel` 默认仍渲染「查询」和「重置」；传 `resetVisibility="auto"` 时筛选项 3 个及以下不放重置（2026-09-30）。「实时筛选不放查询」组件尚不支持，`kit-consumer` 页面暂按组件行为，`library-native` 页面按本条。

出处：知识库《B端筛选组件设计》§筛选逻辑、§按业务复杂度分层、§六种容器的取舍、§效率设计；《列表与表格设计》§筛选区响应式规则

## 3. 空值、零值与数值格式

适用条件：表格、`DescriptionGrid`、指标卡中的所有数值和可空字段。

做法：

- 空值、不适用、未采集：显示统一的占位符，不留白（留白会被误认为还在加载）。占位符只有一种，全项目统一；kit 参照已签收的天枢页面用「—」。
- 0 是真实值，照常显示 0。占位符只表示「无数据」或「不适用」，同一字段在列表页和详情页用同一规则。
- 数值列右对齐，同一列取相同小数位，否则右对齐反而误导。千分位默认开启（`123,220`）。
- 计量单位放表头并右对齐，不在每个单元格重复。百分比写 `12.32%`，事项进展用分数 `12/30`。
- 金额过大时「万」「亿」用汉字。日期需要检索、回顾时用绝对时间 `yyyy-mm-dd`，强调新近程度时用相对时间。
- 加载中用骨架屏，与「无数据」的占位符分开。

反例：

- 未处理告警为 0 时，列表页显示「—」、详情页显示 0。
- 单元格空白。
- 每一格都写「kg」「台」。
- 数值列左对齐，或同列有的带一位小数、有的是整数。
- 同一项目里同时出现 `-`、`--`、`—`、`N/A`。

说明：原文对空值只写了占位符，没有单独写零值；「0 照常显示」由「占位符表示无数据」推出。原文占位符有 `--` 与 `-` 两种写法且自称需要二选一，本条选「—」是沿用天枢已签收页面，待 Owner 确认。

出处：知识库《列表与表格设计》§CRM 表格案例（空值）；《数据格式与数值呈现规范》§一 数值、§三 日期与时间、§五 数据状态；《B端交互十原则-交互前中后的完整回路》§对齐

## 4. 脱敏分级：按还需要识别什么来定

适用条件：页面展示姓名、手机号、地址、邮箱、身份证号、银行卡号，以及金额、时间等敏感值。

做法：先选脱敏程度，再按类型套规则。

- 完全脱敏：金额、时间等特别敏感的值，整个数据用 `***` 代替。
- 部分脱敏：需要保留部分信息用于识别，数字真实位数保留，脱敏部分用 `*` 代替。

| 类型 | 规则 |
| --- | --- |
| 姓名 | 两个字显示第一个字符（`仲*`）；三字及以上显示首尾字符，中间打星（`仲*妮`） |
| 手机号码 | 保留前 3 位与后 4 位（`186 **** 1402`） |
| 联系地址 | 保留省市区，后面打星 |
| 邮箱 | 保留主机名与前三位字符（`123*******@163.com`） |
| 身份证号码 | 高级脱敏：首尾各留 1 位，只能识别地区；中级：前 3 位后 3 位，可识别省市与性别；低级：前 6 位后 4 位，可识别省市区与性别 |
| 银行卡号码 | 高级脱敏：留后 4 位；中级：前 6 位后 4 位，可识别发卡行；低级：前 4 位后 6 位 |

选级别的问题是「这个页面的用户要靠这串数字认出什么」，不是打几个星好看。同一字段在列表页、详情页、导出文件里往往需要不同级别，不要用一套规则覆盖所有场景。

反例：

- 列表页整列显示完整手机号，用户只需要辨认是哪位客户。
- 一刀切：所有页面、所有导出都用同一级别。
- 银行卡「低级」按 4 位还是 6 位写，同一项目内两处不一致。

说明：原文银行卡低级的规则文字是「前四后六」，配套例子却是前六后六，官方原文同样如此；这里按规则文字，落地前需确认。

出处：知识库《数据格式与数值呈现规范》§四 脱敏

## 5. 行操作：查看加至多两个当前状态动作

适用条件：列表或表格的行内操作列，操作随记录状态变化（状态机驱动）。

做法：

- 露出「查看」加至多 2 个当前状态下可执行的动作；超出的收进「更多」下拉。
- 露出哪两个，按当前状态下的使用频率排，高频在前；危险动作不排第一个。
- 「查看」在首列已有链接进入同一详情时可以省略，省下的位置不补新动作。
- 露出的动作按第 1 条定档，B 档在按钮处直接用气泡确认。收进「更多」的动作选中后再确认，B 档改用对话框承接。
- 状态不允许的动作不显示；有状态但无权限的动作置灰并说明原因。

反例：

- 同一行露出 4 个以上动作，操作列宽度挤压主信息。
- 把状态机里的高频动作（如「受理」「标记成功」）收进「更多」，处理人员每次多点一下。
- 所有状态都显示同一组动作，点了才提示「当前状态不可操作」。

与知识包的关系：antd 知识包 `page-templates/list.md` 写「至多露出两个动作，其余进 Dropdown」，未区分「查看」与状态动作。天枢等状态机页面按本条执行，本条优先。

出处：Owner 2026-09-30 裁决；天枢扩页批 2 与 Ant Design Pro 查询表格对照（GLM 5.3 复核）

## 6. 持续内容与通知：保留用户控制

适用条件：已有实时列表、流式输出、通知计数或新内容提示的页面；不因本条给普通页面增加这些功能。

做法：

- 持续内容仅在用户处于跟随位置时自动跟随。用户主动向上阅读后停止拉回；提供恢复到最新内容的入口，阈值按目标页面实际行高和任务验证。
- 支持回车提交的输入框在中文等输入法组合期间不提交。组合结束后的浏览器差异用目标浏览器复现，不能一律套用口播中的“半秒禁发”。
- 通知数量说明待处理、未读或其他已定义语义；圆点说明有新内容。进入、已读与处理完成怎样清除由业务合同确定，不能进入页面就把未处理告警清零。
- 数字增长后保留完整轮廓与相邻内容；截断上限、锚点和增长方向按当前组件与布局确定。科普中的向左增长和 `99+` 是方案，不能覆盖所有底座。
- 通知有可访问名称或关联文案；不把营销内容伪装为需要处理的故障，也不只靠红色区分。

反例：新内容一来就把正在读历史的用户拉到底部；选字回车把半截输入发出；看过告警列表就清空待办计数；三位数通知被祖先裁切。

出处：`<local-path-omitted>` 的输入法与跟随段；`<local-path-omitted>` S5–S6。它们是具体产品细节与口播建议，本条的业务清除条件、阈值及可访问性检查属于 Kit 的适配约定，不采信其中的点击效果或心理因果断言。
