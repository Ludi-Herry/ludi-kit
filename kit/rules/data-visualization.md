# 数据可视化

适用：指标卡、分析图表、运营看板和大屏。关系与拓扑另读 [flow-diagram.md](./flow-diagram.md)。组件与数据类型继续服从当前 design pack 和 manifest。

## 先写业务问题与数据口径

- 说明用户要比较、找趋势、看构成、判断阈值，还是定位异常；图表数量服从问题，不为凑满网格加图。
- 每张图登记指标定义、单位、时间范围、粒度、维度、聚合方式和来源。需要判断时效的数据给出更新时间；同比、环比明确比较区间和计算口径。
- 页面共享时间和筛选时，指标卡、图表、明细与导出使用同一生效范围。局部例外要在对应图表附近说明。
- “0”“无数据”“未采集”“加载失败”按业务含义区分。示例数据标明示例，不把模拟变化写成实时运行结果。

## 选图与读数

| 任务 | 优先考虑 | 检查点 |
| --- | --- | --- |
| 分类或排名比较 | 条形 / 柱状图 | 类别可辨认，排序有依据，数值与单位可读 |
| 连续时间变化 | 折线图 | 时间顺序、粒度和缺失段可辨认；缺失数据不能当成 0 |
| 部分与整体 | 占比图 / 堆叠图 | 分母与总量明确；数值接近、类别过多时改用条形或明细 |
| 单值与阈值 | 指标卡 / 阈值图 | 阈值有业务依据，不能凭颜色推导达标 |

`kit-consumer` 按现有 `TrendChart`、`BarChart`、`DonutChart`、`GaugeChart` 的能力与 `avoidWhen` 选型；manifest 的段数等限制继续生效。合同不支持的堆叠、负值或新图型先记录能力缺口。其他底座使用合同登记的图表入口。

- 比较依赖长度的柱条保留有意义的基线；趋势图调整纵轴时清楚标识范围。多图并排比较时核对单位、比例尺和时间范围，不能用不一致的轴制造可直接比较的印象。
- 图例、系列名、坐标和 tooltip 使用同一指标名称。颜色辅助区分，仍需标签、线型、符号或可访问数据。
- 涨跌方向与业务好坏分开：成本或故障上涨未必是好事，收入下降未必与其他指标同义。趋势箭头表示方向，语义色追溯业务状态与判断规则。
- 背景、网格和装饰让位于数据。沿用主题 Token，不从科普画面或 Skill 默认配色移植整套视觉语言。
- 先用现有组件；DOM/CSS 只用于其能力范围内的简单图。真实数据接入、交互、可访问性和渲染负担决定是否需要已登记图表库。

## 联动、下钻与返回

- 仅在合同要求时增加联动或下钻。点击后的筛选、对象、时间和去向可见；返回保留约定的上层范围和位置。
- 时间快捷项明确实际起止区间；最大跨度、时区和默认周期由业务合同决定，不把案例中的“90 天”写成通用限制。
- 上期对比明确是上一等长区间、自然周期还是其他基准。日期粒度与缺失时段使用同一口径。
- 需要导出或交给负责人处理时，导出与处理入口沿用当前筛选和权限，不因为看板存在就自动新增业务动作。

## 响应式与验收

移动端先确定任务，再决定摘要、图表切换、局部横滚或明细列表；关键数据不能只在 hover 中出现。提供文本摘要与可读取的数据，图表尺寸变化后仍可辨认坐标、图例和异常。

验收核对同一组数据在卡片、图表、明细中的值与口径；执行合同定义的筛选、联动、下钻和返回；检查零值、无数据、错误及规定视口。记录技术、视觉与人工结果，不把静态导出图当交互证据。
