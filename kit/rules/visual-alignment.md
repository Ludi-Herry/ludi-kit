# 视觉对齐与阴影裁切

适用：页面与组件的视觉走查，尤其按钮、菜单、表格、标签、输入框、图标和浮层。先沿用当前底座的 Icon、字阶、行高与间距；下面的检查不授予换库、改 Token 或批量移动图标的权限。

## 先确定对齐对象

| 组合 | 先检查什么 | 判定方式 |
| --- | --- | --- |
| 单行按钮、菜单、输入框前后缀中的图标与文字 | 同一个控件内部的中线关系 | 先检查布局盒与图标槽位居中，再看可见图形与字形是否平衡；`align-items: center` 只能证明盒子按规则对齐 |
| 同一行的正文、数字、单位或不同字号 | 文字基线关系 | 按阅读语义对齐基线，保留当前组件的行高；不能为了盒子中心一致而让文字上下跳动 |
| 图标旁的多行标题、说明或列表项 | 图标与首行还是整块文字对齐 | 按设计规格选择；多行文字整体居中可能把图标拉到段落中间，必须用真实长文案复核 |
| 播放三角、箭头、非对称图标、带留白 Logo | 可见图形的视觉重心 | 先查资源留白和图标槽位，再作必要的光学补偿；矩形中心一致不能替代看图判断 |

中线、文字基线和视觉重心是三种不同参照。文字的行盒包含行高空间，SVG 的 `viewBox` 也可能包含空白。`vertical-align: middle` 有行内字体度量参照，不能直接当成容器中线或光学居中。走查先说明这组元素按哪种参照对齐，不能只写“已居中”。

## 定位与修复顺序

1. 确认实际字体已加载，并核对字号、字重、行高和回退字体。中英混排、数字与单位使用真实内容。
2. 检查容器的 padding、gap、对齐属性和控件高度，排除布局造成的偏移。复用底座组件，不在每个页面另调同一图标。
3. 检查 SVG / 图片的可见边界、透明留白、描边与槽位尺寸。明确是图形偏心，还是布局盒偏移；不为迁就单页擅自裁改品牌或图库资源。
4. 在正常显示比例看实际观感，再用放大截图定位边缘。只有确有偏差时才在组件拥有层作光学补偿，记录对象、方向、依据与适用变体。
5. 核对相同组件在本次涉及的字号、图标、选中 / loading / focus 状态与长文案下是否一致；按项目约定的缩放 / DPR 复核。既有底座已经正确处理的补偿直接复用。

`1px`、`1/8em`、图标必须统一下移等都不是通用偏移量；通过标准是当前组件规格和实际视觉结果。DOM 测量服务于定位，光学通过仍需截图与人工判断。焦点环和点击热区同时保持正确，不能只把画面挪正。

## 阴影被裁切的排查与修复

- 症状：阴影一侧出现硬直边、hover 后只剩半圈，或者圆角在动效中途变成直角。先检查阴影元素到所有裁切祖先及视口的关系，而不是只加 `z-index`。
- 裁切来源包括实际生效的 overflow、`clip-path`、`contain: paint` 和透明窗物理边界。核对两个轴的 computed overflow；不能只看源码写了哪一轴。
- 余量按每一边估算：令 `g = blur + spread`，左 / 右分别取 `max(0, g - offsetX)` / `max(0, g + offsetX)`，上 / 下同理；多层阴影逐边取最大值。`drop-shadow` 无 spread。此估算用于排查和预留空间，不是浏览器模糊像素边界的精确公式。
- 圆角裁内容放内层，阴影放不被裁切的外层；或在实际滚动容器预留足够空间。透明窗还需核对原生窗口尺寸。保留必要的裁切、滚动和圆角，不批量把 overflow 改成 visible。
- `clip-path: inset(...)` 的圆角需单独核对；矩形 DOM 边界不证明曲线像素正确。变更遮罩或动效时，额外观察本次可能暴露缺陷的中途帧。

## 裁切审计怎么执行和记账

涉及阴影、裁切容器或透明窗时，沿用全局的 `clip-audit.js` 门槛，并按以下步骤记录。优先读取本机维护版 `~/.agents/scripts/clip-audit.js`；仅有 Skill 快照时记录所用版本，不能把未执行写成通过。不复制第二份脚本到 Kit。

1. 在当前宿主允许的浏览器 evaluate 中执行读取到的完整函数原文。记录脚本来源、版本或 SHA-256、URL、视口、缩放 / DPR、状态和 root；浏览器方法名按实际工具契约使用。
2. root 选能包含目标阴影元素的父容器。现行脚本遍历 root 的后代，不检查 root 自身投影；root 未找到、目标没被覆盖或存在运行错误时都不能判通过。透明 / 无边框窗按实际需求加入 `{ viewport: true }`，并在真实桌面运行时核对物理窗口边缘。
3. 分别进入默认、真实 hover、已定义的展开 / 弹层和动效落点状态再运行；只覆盖本次相关状态。脚本自动套用部分 hover 阴影不能替代真实 hover，也不替代观察动效中途帧。
4. 保留原始 `{ ok, cut, hidden, issues }` 输出。现行脚本顶层 `cut` 是半截裁切问题的计数，`issues[].cut` 才是该条裁切距离的 px 值；`hidden` 是整侧隐藏候选，逐项说明是否符合预期。issues 输出被截断时先按区域补查完整发现，不能只留前几条就声称已处理全部。
5. 无运行错误且 `cut === 0` 是既有必要条件；截图复核阴影、圆角、透明像素与当前状态。跨域图片、复杂 clip-path、遮罩及窗口外观仍可能需要人工判断。`cut: 0` 只说明本次脚本范围与状态没有命中半截裁切，不等于整个页面的视觉验收通过。

已知滚动轴盲点：现行脚本遇到 `overflow: auto/scroll` 且该轴确有溢出时，会跳过该滚动容器的对应轴，并停止检查更外层祖先的同一轴。`cut: 0` 不覆盖这些边界，加入 viewport 检查也不能补回已停止的轴。对本次涉及的滚动口在起点、中段、终点和相关状态截图复核，人工核对可见投影与外层裁切；不把脚本通过当作滚动边缘无裁切。

发生故障时按“触发状态 → 实际裁切祖先 / 对齐参照 → 根因 → 修改所属组件 / 规则 → 复测结果”留档。截图和原始输出放项目现行 evidence 目录，失败现场保留；同一 finding 在多个走查项只保留指针。

## 来源与适用范围

CSS 中线与基线术语参考 [CSS Box Alignment](https://www.w3.org/TR/css-align-3/#baseline-values)、[CSS Inline Layout](https://www.w3.org/TR/css-inline-3/#alignment-baseline-property) 的工作草案；具体浏览器支持按目标环境验证。本文件的场景表与修复顺序是 Kit 的走查约定，不要求启用草案新增属性。

光学对齐、裁切分层与多状态验收参考用户开源的 [desktop-agent-ui 组件细节](https://github.com/Ludi-Herry/desktop-agent-ui/blob/44653f97065f71de662a07d1aa4547870962b029/references/components-motion.md#光学对齐optical-alignment)、[验收清单](https://github.com/Ludi-Herry/desktop-agent-ui/blob/44653f97065f71de662a07d1aa4547870962b029/references/acceptance.md) 和本机 `clip-audit.js` 实现。远端清单将顶层 cut 称为像素数，本文件按实际脚本明确为问题计数；未修改上游。第三方 Claude 桌面反向手册是实现参考，其固定数值与性能宣称不作为本项目已验证结论。
