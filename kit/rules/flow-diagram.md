# 流程图与关系图

适用：页面中的审批流程、状态流转、系统关系、拓扑和依赖图，以及交付文档里的图示。先分清图的含义，再选表达方式。

## 语义与范围

| 要回答的问题 | 表达方式 | 需要保留的信息 |
| --- | --- | --- |
| 谁在什么条件下做下一步 | 流程图 / 泳道图 | 角色、动作、分支条件、结果和异常出口 |
| 对象允许怎样改变状态 | 状态图 | 当前状态、触发事件、允许的迁移及失败路径 |
| 谁连接谁、谁影响谁 | 关系图 / 拓扑图 | 真实端点、关系方向、关系类型和跨组连接 |
| 同一个任务当前走到哪一步 | Stepper | 已完成、当前、后续步骤；有分支时不能仅靠步骤条交代 |

图中的角色、对象、状态与条件追溯项目的 `business-context.json`、`pages.json`、`flows.json` 及其登记来源。文档图是这些事实的视图；不能由绘图 Skill 另建一套业务流程或自行补造异常分支。缺少关键条件时保留待补。

## 布局与连接

- 先摆清主要路径和分组，再减少交叉。直角线是可选布局策略；斜线本身不判错误。
- 箭头、线型和标签区分方向与关系；同一种含义保持一致。流程分支写条件，回退线说明回到哪里。
- 多条边合并成总线后仍需辨认真实端点。交互图可点选节点高亮完整关联路径；静态图通过标签、分组或拆图保留关系，不依赖 hover。
- 折叠节点时保留分组数量和异常摘要；监控任务中的异常优先可见，展开后能定位同一对象。
- 颜色用于有限的状态或重点，异常同时有文字或图标。正常节点是否用灰色由项目主题决定，不覆盖现有状态色映射。

## 跨端与交互

- 按移动端已登记任务决定保留哪些能力；不把整张桌面图缩小到文字不可读。
- 关系图可以按业务分组改成可展开列表，但网状关系不能直接当树。跨组关联通过上下游、关系入口或详情保留。
- 层数取决于实际可用宽度、字号、缩进、图标和操作占宽。长名称可辨认、关键动作可触达才算可用；“三层”“16px 缩进”不作为统一硬门。
- 深层内容按任务选择局部展开或进入下一层页面；保留当前位置和返回路径。移动端路径避免无限折行，截短后仍能返回所需层级。
- 触屏端用点击提供 hover 中的必要信息。简单状态摘要可用底部面板，复杂编辑或大量详情使用详情页；关闭入口、平台返回行为和关闭后的原位置都要检查。
- 平移、缩放、节点编辑、键盘导航和布局引擎优先复用合同已有能力。静态 SVG、Mermaid 或说明图不能冒充已经可编辑、可操作的业务画布。

## 验收

选择一条真实主路径、一处已定义分支或跨组关系、一组包含异常的折叠节点核对。分别记录端点、条件、方向、展开定位和返回结果；合同没有对应场景时记不适用。
