# 反模式

在生成和评审页面时优先检查这些高频错误。

## 页面结构

- 卡片套卡片。
- 页面级标题放进内容卡片。
- 列表页没有筛选区。
- `DataGrid` 直接挂在页面根容器。
- 详情页套用列表页结构。
- `Tabs`、`SideNav` 和 `Stepper` 混用。
- 用近似色替代 Token。

## 状态表达

`Badge` 的 variant 表达业务语义，显示文案由项目数据适配层提供。映射表维护在 `projects/<id>/status-copy.md`，同一业务语义在项目内保持稳定。

| 业务语义 | variant |
| --- | --- |
| 正常、完成、可用 | `success` |
| 等待、预警、需要关注 | `warning` |
| 错误、危险、阻断 | `danger` |
| 中性信息 | `info` |
| 进行中 | `processing` |
| 当前或主状态 | `primary` |
| 次要状态 | `secondary` |
| 项目已定义的稳定分类 | `geekblue`、`cyan` 或 `purple` |

不要把业务状态文案写进 kit 组件，也不要为文案差异增加 variant。颜色只能辅助语义，页面仍需提供可读文案。

## 非法操作反馈

业务规则拒绝操作时，反馈要说明：

1. 哪个动作失败。
2. 失败发生在哪个对象或页面。
3. 失败原因。
4. 当前允许的状态变化。
5. 用户下一步可以去哪里或做什么。

只有“操作失败”的反馈不完整。
