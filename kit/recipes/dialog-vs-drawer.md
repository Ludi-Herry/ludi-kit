# Dialog 与 Drawer 选择

先从 `components.manifest.json` 确认当前公开浮层组件。现有 `ConfirmDialog` 处理短确认和危险操作，`Drawer` 处理右侧详情与轻编辑。完整创建或编辑流程使用独立表单页。

## 选择规则

- 删除、停用、清空、批量冻结等动作先按 [确认分级](../rules/interaction-decisions.md#1-确认分级先问能不能撤销) 判断；C 档短确认使用 `ConfirmDialog`。
- 右侧查看详情或轻编辑：`Drawer`。
- 完整新建或编辑流程：独立 form page。
- manifest 未提供的浮层能力：先记录真实项目 feedback，业务页不临时自造。

## ConfirmDialog

- `title` 说明动作，`description` 写清对象、数量和影响。
- `confirmLabel` 使用具体动词；危险操作传 `danger`。
- 页面持有 `open` 状态和业务请求；`loading` 期间阻止重复提交与取消。
- 遮罩点击不关闭；取消或 Esc 关闭后，焦点返回触发按钮。
- 触发按钮会随选择态卸载时，把稳定数据区 `ref` 传给 `focusFallbackRef`。
- 批量危险操作先用 `BulkActionBar` 显示选中数量，再组合 `ConfirmDialog`。

## 从列表进入详情

适用条件：列表或表格里点击对象名称进入详情，需要选择打开方式。

做法：默认点击对象名称进入详情，再按下表选打开方式。

| 方式 | 什么时候用 |
| --- | --- |
| 同页展开 | 首选，交互最自然；展开的内容高度不超过一屏 |
| 抽屉 | 详情超过一屏，同页展开不便操作 |
| 独立页 | 详情需要单独分享给他人，或属于复杂的沉浸式任务 |
| 双栏（左列表右详情） | 每条详情都可能有用户感兴趣的内容，需要在不同条目间快速切换查看和处理 |

反例：

- 详情内容两屏高，仍在表格里行内展开，把后面的行推出视野。
- 详情需要发给同事查看，却做成抽屉，没有可分享的页面。
- 用户要连续处理几十条，却每次跳整页、返回后丢失列表位置和筛选状态。

说明：最后一条反例由「双栏」的适用条件推出，原文没有单独写。
