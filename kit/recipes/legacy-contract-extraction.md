# 从老代码提炼行为合同（草案）

适用：T7 式「老框架 → 新框架」迁移的第一步——从老项目读出一套**与框架无关、可被浏览器断言复述**的行为合同，作为新旧两版共同的验收基线。配套走查心法见 [legacy-walkthrough-tianshu.md](legacy-walkthrough-tianshu.md)。这是草案，不注册 canonical workflow；首个实例为 2026-10-05 T7（`<local-path-omitted>`）。

## 心法

合同回答「用户看得到、点得到、读得到什么」，不回答「老代码怎么写」。视图实现禁止逐行翻译；**数据与流转语义（seed、存储键、筛选分页、状态字典、错误文案）属于合同本身**，必须逐字节保留——完全相同的初始数据是两版可断言比较的唯一基础。

## 提炼顺序

1. **定范围**：列表、表单、详情、权限四类代表模块各挑 1 个（挑动作最齐的：create/edit/delete/export 俱全者），加上本轮已在老版延展的目标页。
2. **先全局后页面**：全局合同（壳层与导航、角色权限双层、请求/数据语义、通用文案与状态色、空态/错误态、控件 id 约定）写在前，页面合同只写差异（列、筛选、表单、行操作、createLabel、detailMode、数据锚点）。
3. **每条附出处**：`文件:行` 引用老版源码，不抄代码；描述要具体到可断言（文案逐字、行数、首轮值、确认框标题与正文）。
4. **数据锚点单列**：每个页面写明 seed 行数与首行值（如 models 24 行、首行 `星舟一号-01 / TS2025000001`）——断言靠它选确定性目标，不靠随机行。
5. **权限落到具体页面**：双层权限（UI 隐藏 + 请求层拦截）挑权限代表页写出每角色看到/看不到哪些按钮。

## 断言基线怎么立

- 定位优先级：角色与文字 > 合同约定的控件 id（`filter-{prop}` / `edit-{prop}`）> 跨库同名类（`.el-message-box` / `.el-dialog` / `.el-table__body-wrapper` 容器级）。
- 先在老版跑通留证据（命名 record + 失败落 JSON + 截图），再原封不动跑新版；断言不因新版红而放宽。
- 已知陷阱（element-ui ↔ Element Plus 同宗移植时都会踩）：
  - 字体图标经 `::before` 私有区字符进入可访问名（`"\uE62E新增设备"`），按钮名必须用**子串匹配**，容器/行作用域消歧。
  - 固定列克隆：整表 DOM 复制，行计数锚 `.el-table__body-wrapper`；克隆行可见文本只有操作列，状态文案断言走主表行，按钮点击走 `.el-table__fixed-right`（克隆在后，行序一致）。
  - `getByRole('listitem', { name })` 对下拉项不可靠，用 `getByRole('listitem').filter({ hasText })`。
  - 纯 hash 差导航不重挂载同 pageId 组件，预填筛选会残留；断言 harness 用 host 查询位参数强制整页重载后，`waitForURL` 的 glob 不能再含 `/#/` 字面量。
  - EP 默认英文 locale，分页「共 N 条」需显式 `zh-cn`；全局 small 密度与老版对齐。
- 断言要覆盖：壳层、每页首屏（标题/筛选/表头/分页条数）、关键交互闭环（新增-校验-落库-筛中、删除-确认文案-消失、处理流转-必填-状态翻转、跳转链路）、权限三角色、种子确定性（计数文案）、console 0。

## 重写与偏差纪律

重写时允许按新框架原生件优化，但合同外的每处行为差异必须进「有意改动清单」（是什么、为什么、断言是否覆盖）；合同内项不许悄悄放宽（如确认分级、必填校验、计数口径）。微前端回挂时用一张总开关 + 逐页开关的迁移表，回退=总开关关掉整体回到老版，不做逐文件还原。
