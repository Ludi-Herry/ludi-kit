# Loading、Empty 与 Error

为页面和区块提供可区分、可恢复的状态。状态出现在哪里，反馈就放在哪里。

## Loading

优先使用组件的 `loading` prop。文案说明正在加载的对象或动作，避免只显示“加载中”。

## Empty

使用组件的 `empty` slot。说明为什么当前没有内容，并给出与权限和业务状态一致的下一步。筛选结果为空时保留筛选条件和清除入口。

## Error

- 字段错误：控件 `status="error"`，并在字段附近说明输入问题和修改方法。
- 区块错误：保留区块标题，说明失败对象、原因和重试入口。
- 页面错误：说明当前无法完成的任务、受影响范围和恢复路径。
- 权限错误：使用 permission-state recipe，不能用空态掩盖 403。

错误文案至少回答发生了什么、发生在哪里、现在怎么处理。捕获异常只用于控制技术细节展示，不能丢掉可行动信息。

## 五态检查

适用条件：每个列表页、详情页和带异步数据的区块，生成完成前和评审时。

做法：逐页核对五种状态都有设计与实现。

1. 理想状态：数据完整。
2. 部分状态：只拿到一部分数据或权限，处理方式参考空状态。
3. 加载状态：见上文 Loading。
4. 错误状态：见上文 Error。
5. 空状态：见上文 Empty。

反例：

- 列表页做了加载与失败态，详情页只做了理想状态。
- 列表页没有空态，筛选无结果时只剩表头。

出处：知识库《B端页面模板-六类页面的骨架与选型》§四 异常页（五种状态提醒）

## 异常页四要素

适用条件：整页级异常，包括 404 资源未找到、403 无权限、500 服务出错、浏览器不兼容、加载失败。

做法：四个要素齐全。

1. 配图：缓解用户烦躁；所用组件不带配图时，至少保留其余三项。
2. 异常代码或问题：一眼看出是哪类异常。
3. 异常描述：用简明的语言说明原因，不用晦涩的技术术语。
4. 建议操作：协助处理或引导回正确路径，例如返回、重试、申请权限。

403 用 `ForbiddenState`，写法见 [permission-state.md](./permission-state.md)。

反例：

- 只显示一个大号「404」，没有描述和下一步。
- 描述直接抛出接口报错文本。
- 没有任何可点击的出口，用户只能手动改地址栏。

出处：知识库《B端页面模板-六类页面的骨架与选型》§四 异常页
