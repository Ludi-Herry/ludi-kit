# 页面设计走查（试运行）

写码后，按合同与设计规格检查页面是否支持用户任务。只报告指定页面的发现；技术通过、视觉判断和 Owner 签收分别记录。此 recipe 与 `review-*.mjs` 不接入 validate，不生成新的冻结通过记录。

## 基线与证据

读取目标页 `flowCard`、`intentCard`、`layoutTree`、业务合同、当前 design pack、状态文案与已有规格。合同 adapter 在 `foundations/adapters.json`；按目标的 `frontendFoundation.adapters` 选用，不凭清单改底座。

每项填写 `pass / finding / not-tested / not-applicable`。通过也必须写“页面 / 状态 / 条件或动作 / 实际观察 / 证据定位”，例如“device-list，筛选生效后阶段数字与同条件结果逐项相符，见运行记录与截图”。不能只写“符合规范”。不适用写合同理由，未测试写缺少的输入。证据要能定位文件行、页面 URL、DOM 测量、交互断言或截图；静态源码不能单独证明交互已发生。

## 六个维度

| 维度 | 可判定的方法 | 机器覆盖与人工补充 |
| --- | --- | --- |
| 层级 | 对照首屏与区块顺序，找主操作、对象身份及状态；检查标题是否被塞进内容卡片；沿一条真实任务定位下一步 | `lint.react-antd-project` 可查导入与组件写法，不能判断任务主次；用 `browser.playwright-react` 执行动作，`visual.playwright-screenshot` 留图，由人逐区对照合同 |
| 布局与滚动归属 | 在已定视口检查每个区块、固定列遮罩、底部操作条；沿同一内容的祖先路径找实际可纵滚的容器；滚到起点、中段、终点确认内容能到达 | 既有 browser adapter 检查实际 DOM / overflow；新增 `review-scroll-ownership.mjs` 报告嵌套纵滚候选。独立侧栏、横向表格、浮层内滚不靠容器数量判错；人核对候选是否承载同一内容及是否有明确例外 |
| 状态载体 | 分别触发合同要求的空、加载、错误、权限状态；检查反馈是否出现在发生的字段 / 区块 / 页面，且有正确恢复动作 | 既有 browser adapter 可断言状态与恢复；人检查 `empty-loading-error.md`、`permission-state.md` 和项目状态文案的对应关系。无状态输入时记录未测试，不伪造 API |
| 语义色 | 对照项目状态映射，同一业务语义保持一致；禁用、进行中、警告与危险有文本区分；核对当前主题和变量来源 | 当前 lint / token 检查发现硬编码与错误写法；合法 token 用错语义仍需人核对。不能把颜色有效等同于含义正确，不能为检查临时新增暗色主题 |
| 动效 | 执行关键状态切换，检查结果、焦点与空间关系能否跟上；启用 reduced-motion 后重做；确认加载动效与真实进度相符 | browser adapter 可测 DOM 变化、焦点及 reduced-motion；时序是否清楚和无谓等待由人判断。无合同要求的动效记不适用，不因此新增动画 |
| 文案 | 核对动作动词、对象、数量、后果、失败原因、下一步；同一状态、单位、0 与空值跨页一致 | 静态检查 / `check-prose.py` 只能筛写作问题；真实反馈与合同一致性由 browser 断言和人工核对。技术异常不直接展示为用户文案 |

本批只实现滚动归属的试运行增量；上表其余维度复用现有 adapter 或人工步骤，没有新增自动门。既有 lint 能覆盖的颜色、导入或 token 问题不重复造脚本。

## 17 项体验覆盖

参照项目 [HiUI 评估 §11.1、§11.4](../../docs/ANALYSIS-hiui-5-integration-2026-08-08.md) 已核实的“操作高效 7 / 符合直觉 5 / 体感 5”结构与通过项必须写证据的做法。以下是合并 CloudAI 六个设计维度后，按 kit 合同改写的 17 项；编号是本地编号，不宣称与上游逐字或逐 ID 对应。上游原始检查单本次读取失败，具体原项名称未重新核验。

| ID | 覆盖项与判定方法 | 六维归属 / 证据要求 |
| --- | --- | --- |
| E1 | 高频任务入口：从合同入口完成主任务，不能出现缺入口或死路 | 层级；入口、动作、结果记录 |
| E2 | 查询效率：按规定的筛选分层找到同一个目标对象，条件有结果可见 | 层级、布局；筛选计数与对象断言 |
| E3 | 快捷与批量：合同已有的批量或快捷动作能减少重复步骤，并保持对象范围 | 层级、状态；选中集合与实际操作结果 |
| E4 | 输入负担：默认、记忆和校验符合合同，隐私字段不被误记忆 | 状态、文案；刷新与校验前后证据 |
| E5 | 上下文连续：列表 → 详情 → 返回，身份、筛选与结果按合同保持 | 层级、布局；同一对象跨页记录 |
| E6 | 操作反馈：触发后有准确进度或完成反馈，不把点击成功当业务成功 | 状态、动效、文案；动作与状态变化 |
| E7 | 错误恢复：保留可继续的上下文，重试 / 重置 / 返回确实可用 | 状态、文案；失败与恢复路径 |
| I1 | 导航与结构：同页分区、跨页入口、步骤的组织与任务一致 | 层级；合同区块与实际 DOM / 图 |
| I2 | 主次明确：主操作、关键字段、次要工具能按首屏要求定位 | 层级、语义色；首屏对照与动作位置 |
| I3 | 状态一致：空、加载、错误、无权限不混用；同枚举同文案与色义 | 状态、语义色、文案；各状态证据 |
| I4 | 控件符合用途：manifest / pack 中的选型与当前业务语义相符 | 层级、状态；组件与合同映射 |
| I5 | 风险可理解：确认与权限说明包含对象和后果，遵守既定风险分级 | 状态、文案；确认内容、取消和允许结果 |
| F1 | 可读与密度：关键身份、默认排序列与单位可读；0 与空值可区分 | 层级、布局、文案；图与字段对照 |
| F2 | 响应式可达：指定视口及表格横滚三处都能到达关键内容，固定列不遮挡 | 布局；尺寸、横滚位置与视觉证据 |
| F3 | 滚动可预期：同一内容不会无说明地在两层纵滚间抢滚轮 | 布局；滚动祖先测量与人工复核 |
| F4 | 焦点与运动：状态切换后焦点合理，键盘操作可达，减弱动效设置有效 | 动效、布局；键盘与 reduced-motion 记录 |
| F5 | 语气与节奏：反馈清楚、不过度打断；没有无真实结果的假进度 | 文案、动效；完整操作过程与反馈 |

同一发现可对应多个 ID，但只登记一条 finding；17 项覆盖表保留指针，避免重复计数。不能为凑齐通过项扩张页面能力。

## 按内容补查

下面是既有六维 / 17 项的检查细化，不增加自动门或固定通过数量。仅检查目标页面已定义的能力，证据与 finding 沿用上面的格式。

| 命中内容 | 要观察的结果 | 对应项 |
| --- | --- | --- |
| 图表 / 看板 | 同一对象、时间、筛选在卡片、图表、明细与导出中的值和口径一致；0、缺失和失败可区分；规定的联动、下钻、返回可用 | E2、E5、E6、I3、F1；[数据可视化](../rules/data-visualization.md) |
| 流程 / 关系图 | 连接端点、方向、分支与合同一致；合并线仍能识别关系；折叠后异常可见；跨组关系在移动表达中可达 | E1、E5、I1、I4；[流程与关系图](../rules/flow-diagram.md) |
| 时间 / 标签 / 全选 | 快捷项对应明确区间；受限日期与比较基准正确；长标签有完整名单；最终选择集合与全选规则一致 | E2、E4、I3、F1 |
| 输入 / 浮层 / 热区 | 字段名称始终可见；失败保留输入；关闭与取消可达；焦点和原位置恢复；相邻点击目标不重叠 | E4、E7、I5、F2、F4 |
| 使用外部 Skill | 视觉、依赖、Token、导入与文件写入符合项目合同；样式建议未替换已签收基线；真实浏览器检查与静态产物分别记账 | I4、F2、F4；[Skill 边界](../docs/design-skill-routing.md) |
| 图标 / 文字对齐 | 明确中线、基线或首行参照；核对可见图形、字体与 SVG 留白，真实字号 / 状态下没有漂移；DOM 居中测量与光学看图结论分别留证 | I2、F1、F4；[视觉对齐](../rules/visual-alignment.md) |
| 阴影 / 圆角 / 裁切 | 目标元素在脚本 root 内且被覆盖；相关状态无运行错误且 cut 为 0；hidden 有人工解释，截图复核圆角与实际投影 | F2、F4；[裁切审计步骤与字段](../rules/visual-alignment.md#裁切审计怎么执行和记账) |
| 已声明的移动任务 | 在目标环境检查安全区、键盘弹出 / 收起、主操作可达与恢复、平台返回 / 关闭、手势与内外滚动；源码正则或桌面窄窗不能单独证明触控与键盘通过 | E5、E7、F2、F4；[移动参考与边界](../docs/design-skill-routing.md#用户开源三套-skill去重与取舍) |

## 滚动脚本用法与边界

在 `kit/` 执行：

```powershell
node scripts/review-scroll-ownership.mjs
node scripts/review-scroll-ownership.mjs --page alerts
```

脚本只服务天枢本批：取 `pages.json` 中除 `firmware-form`、`flashing-form` 外的 12 个页面 ID，覆盖两个详情页；两个表单页与固件编辑别名不在这次“12 页”采样内。视口 1440×900 和 1024×900 是诊断采样，不能登记成新产品断点。

用现有 esbuild 在内存中编译目标应用，只在 `127.0.0.1:5440` 提供内存 HTML / JS / CSS；不读取或开放整个仓库，不启动编辑器插件。Playwright 使用独立浏览器 context，拒绝外部请求，不写截图或构建文件。结束时关闭浏览器与自己的 server；端口冲突时报错，不自动换端口，也不碰其他服务。

判据：可见节点满足 `overflow-y: auto/scroll` 且 `scrollHeight > clientHeight + 1` 时记为实际纵滚容器；document 使用 `scrollingElement` 单独计入。在内容区内沿祖先路径寻找同时可滚的容器对，输出选择器、可视高度、内容高度和滚动最大位移。1px 仅作 DOM 舍入容差，不是产品验收阈值。独立兄弟区域不判嵌套；水平滚动只记录，不判纵滚问题。

输出为 JSON Lines；`candidate` 需要人工判真问题 / 误报 / 合同待定。exit 0 表示执行完成且未发现候选，exit 1 表示已完成但有候选，exit 2 表示运行异常或源码漂移导致证据不完整。以上均不阻断项目 validate。源码与 HEAD 有差异时报告相关文件并跳过受影响页；源码在构建 / 测量间变化也作无效证据。记录后稍后只重跑该页，禁止还原、stash 或修复并行任务文件。

只测初始 ready 状态，不覆盖长数据、所有展开区块、Modal / Drawer、空错权限或 reduced-motion。没有候选只能证明本次 DOM 采样未命中；完整六维和 17 项仍需逐项补交互与人工证据。新脚本未达到“既有负例 + 至少一次真实失败”准入条件前，保持试运行。

## 交回格式与来源

交回记录页面范围、源码哈希、原始命令输出与 exit code、每条 finding 的位置 / 条件 / 观察 / 合同依据 / 建议 / 严重度，以及人工复核结果。真问题按现有项目范围处理；P2 和范围外问题交回 Owner，不顺手修页面。脚本候选不自动升成硬错误。

方法来源：CloudAI `@cloudai-design/oneskill@0.6.1`（MIT）外置源码包中的 `CloudAI-UI/design-review.md` 与 `design-system/{hierarchy,layout,states,color,motion}.md`；版本拆解位于 `<local-path-omitted>` §6。HiUI 固定快照 `f056c80e792aa8c0ca1ef0cdac8244abd7c58940` 的证据机制以项目评估 §11 为本批已读依据。仅借方法和结构，不复制上游文案、代码或安装其 Skill。
